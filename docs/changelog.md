## Unreleased

- **移除伞形 `jj-team`，保留三个 sibling 引擎**：`jj-team` 是「调一次即预置常驻团队」的总入口——先量可派发项数定花名册规模，之后同会话直接给任务即为团队活。2026-09-22 那次 Grok 实测暴露了它守不住自己的账本：新车道不进 `parallelism.lanes`、代码已合 `dev` 而那条任务仍是 `in_progress` 且 `closed_at: null`、会话 id 读到了却没有 rebind 命令可落。账本读起来和一份新建的一模一样，而它正是唯一一份在飞记录——这是它最难被察觉的一种坏法。根因不是粗心，是结构性的：`每个步骤边界记得去改一段嵌套 JSON` 本来就没有宿主守得住，而团队模式把整个产品的正确性都押在这句话上。三个 sibling（`jj-team-coordinate` / `jj-team-lifecycle` / `jj-team-swarm`）是显式按名调用的单轮执行引擎，与伞形的自动预置是两套东西，本次一行未改、继续可用。随之消失的是「常驻团队」这个概念本身、`TEAM-*` 状态、调用即预置与会话静默 resume，以及 `~/.jj-flow/team/` 兜底目录——移除后没有任何引擎写它，`homeLayout.mjs` 里那一行承诺因此一并删除，留一句做不到的承诺比没有承诺更糟。设计取舍的推理链移入执行计划完成记录，被删文档的原文索引指向 git 历史。合约：`tests/jj-team-skills-contract.test.mjs`。
- **`jj-end` 不再被 `.workflow/` 台账阻断收工**：批量收工的预览把「未选中的脏路径」整批算作阻断项，而团队运行期间 `.workflow/` 底下必然是脏的——那是本产品各引擎共用的状态根。2026-09-22 那次 Grok 团队的收工现场：第一次预览报了 66 个阻断项，预览来回出了三版，一次 commit 被 hook 拦下，最后靠手工 `Move-Item` 把团队账本挪走才关得过。现在 `.workflow/` 路径拆出来进新的 `workflow_state_paths[]`，只报告不阻断；`assertClean` 同步放过它们，否则预览不拦了、`execute` 还是会在同一批路径上失败。**无关的脏活照旧阻断**，由专门用例守着——拆的是阻断条件，不是收工前的检查。合约：`tests/end/runner.contract.mjs`。
- **`docs:check` 修好：更新日志改为投影，站点页面不再写 include 指令**：`docs:check` 在 main 上一直是红的——93,032 字节的更新日志页正好在 VitePress 打包阶段的内存墙上，默认 4 GB 堆耗尽，报的是一段看不懂的 native 栈。根因不在页面积，在一行示例代码：`docs/design-docs/docs-site-vitepress.md` 的文件树清单里写了 include 指令当例子，而 VitePress 的 include 是正则替换、不认代码块；又因为 Windows 的 NTFS 大小写不敏感，`../CHANGELOG.md` 解析到的就是 `docs/changelog.md` 自己，那一页再递归包含根 `CHANGELOG.md`——两页各带一整份更新日志，正是切分要避免的那件事。修法是两件：两页改由 `scripts/sync-changelog-pages.mjs` 从 `CHANGELOG.md` 的两个区域投影并签入仓库（`CHANGELOG.md` 仍是 release-please 的唯一来源，正文一字不改），`scripts/check-changelog-split.mjs` 查五件事——区域标记成对且闭合顺序对、没有版本标题掉队、两页等于投影、每页在 80,000 字节预算内、**站点页面里一行 include 指令都不许有**（它能不能解析取决于文件系统大小写敏不敏感，那不该由运气决定）。构建从 OOM 变成 20.96 秒。
- **两条文档 lint 的扫描面差集第一次被机械计数**：`lint-doc-pointers.mjs` 的文件面取自 git，`lint-doc-tables.mjs` 取自 `documentation_policy`，两个面从来不是一样宽，而这个差此前没有任何东西数过。新增 `scripts/doc-scan-surface.mjs` 对两份面取差，要求差集里每个文件都被一条有名字的规则解释（`excluded_paths` 或 `non_documentation_paths`），解释不了的非零即红；`docs:check` 第 2b 步在构建之前执行它，结构缺陷因此立刻失败，而不是等一个几分钟的 build 之后再失败。固定为不变量的是**未解释失败 = 0**，而不是差集本身的大小：差集随仓自己增长，每增加一个 skill、每增加一份示例它都变大，把那个数固定为断言的那天就是它过期的那天。反方向（表格 lint 可见而 git 不拥有）**没有**解释规则——指针 lint 索引不到的文件是它的覆盖缺口，一条 manifest 键会把这道缺口盖住。`npm run docs:surfaces` 可单独执行该守卫。合约：`tests/doc-scan-surface.test.mjs`。
- **`documentation_policy.current_roots` 纳入 `skills/`，四个手点文件退场**：出厂 Markdown 此前只有 `docs/` 整树加 8 个手点文件进入扫描集，96 个出厂 `.md` 一个都没进入过扫描集。现 `current_roots` 为 `["docs", "skills"]`，`current_files` 里四个 `skills/*/SKILL.md` 随之删除——同一个目录不能既被整树扫描、又被逐个点名，两份声明会各自漂移，而这次漂移的方向正是那 96 个文件从未被审过。合约：`tests/doc-scan-surface.test.mjs`。
- **`documentation_policy` 新增 `non_documentation_paths` 键，并由 `harness:check` 两条新规则守着**：解释规则本身会腐烂。一条指向不存在路径的规则不报错，只让差集里少一条解释，表现是某个新文件突然「未解释」，看起来像别的地方坏了（`HNS-DOC-010`）；一个路径同时是「当前文档」和「不是文档」时，「为什么这个文件不在表格 lint 面里」会有两个答案，等于没有答案（`HNS-DOC-011`）。schema 的 `additionalProperties: false` 同步声明该键，manifest 与 schema 不可能各自漂移。合约：`tests/harness-check.test.mjs`、`tests/doc-scan-surface.test.mjs`。
