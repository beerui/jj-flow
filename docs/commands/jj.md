# jj — 说不清时帮你选入口

**它帮你做什么：** 你只知道“想用 jj-flow”，但还没想好是接入、做需求、迁移、审查还是收工时，先把意图分到合适的入口。

**它不做什么：** 不替你猜项目目标，不把模糊请求直接当成迁移，也不代替被选中的工作流。目标不清时会先问你。

| 你用的工具 | 怎么喊 |
|------------|--------|
| Codex | `$jj …` |
| Claude / Grok / Qoder | `/jj …` |

## 什么时候用

- 你只想描述目的，不想先记住命令名
- 你在多个入口之间犹豫，需要一个安全的分流起点

**不该用 jj 的情况：** 已经明确知道要做什么时，直接说 `$jj-ralph`、`$jj-same` 等原生入口更快；jj 只是路由，不会额外建立一套任务记录。

## 开始前

1. 在要处理的业务仓库对话里使用。
2. 说清“要改哪个仓、要不要迁到别的仓、是否只是收工”等目的；不用提供内部编号。

## 第一次这样用

**你说：**

```text
$jj 我想把项目A 做好的登录提醒搬到项目B
```

**Agent 会做：**

1. 识别你是在做地图接入、同源迁移、多项目调度、单仓需求、只读审查还是 Git 收工。
2. 给出对应入口和理由；例如上面的请求会指向 [same](jj-same.md)。
3. 如果关键信息不足，先问目标、仓库或分支，不会默认选择迁移。

**你会看到：** 一段短的“你说的像 → 推荐入口”说明，例如：

```text
这更像同源迁移：建议使用 $jj-same。
如果只是当前仓库做需求，则使用 $jj-ralph。
```

**怎样算做完：** 你已经拿到明确入口并转入该入口；真正的改动、验收和记录以被选中的 skill 为准。

## 常用说法

```text
$jj 当前仓加入全局地图
$jj 只改这个仓的关闭按钮
$jj 把项目A 的能力交接到项目B、项目C
$jj 多个项目一起派，先给我预览
$jj 审查刚才的改动
$jj 代码做完了，帮我收工
```

## 做完之后

| 你的目标 | 推荐入口 |
|----------|----------|
| 接入地图或补知识 | [init](jj-init.md) |
| 当前仓从做到验收 | [ralph](jj-ralph.md) |
| 搬到同源仓 | [same](jj-same.md) |
| 多项目预览、批准、派发 | [dispatch](jj-dispatch.md) |
| 只读审查落盘 | [review](jj-review.md) |
| 提交、推送、合分支 | [end](jj-end.md) |
| 明确要求多角色或方案搜索 | 可选的 [team 工具](jj-team-coordinate.md) / [evaluated](jj-evaluated.md) |

## 进阶

分流优先级是：接入 → 迁移 → 多项目 → 单仓 → 审查 → 收工；离线复盘和 team 引擎只有在你明确提出时才会进入。可选 team 入口只安排这一轮怎么做，不能代替 ralph 或 dispatch 的验收记录。

## 记录在哪

jj 本身不写业务记录；记录位置由它转到的入口决定：ralph 在 `.workflow/ralph/`，dispatch 在 `~/.jj-flow/`，same / review 则写各自任务与目标仓的证据。
