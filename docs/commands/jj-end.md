# end — 收工（提交、推送、合分支）

**它帮你做什么：** 一次做完 Git 收尾：拉最新 → 提交本任务 → 推工作分支 → 切到合入分支同步 → 合并 → 推合入分支 → 回到工作分支。

**它不做什么：** 只动 Git。不归档 ralph 任务、不改调度记录、不写业务代码。归档过的任务想再改，仍然去 [ralph](jj-ralph.md)。

| 你用的工具 | 怎么喊 |
|------------|--------|
| Codex | `$jj-end` |
| Claude / Grok / Qoder | `/jj-end` |

也可以直接说「收工」「合到 dev」「结束任务提交并合并」。

## 什么时候用

- 功能改完了，要正式提交并推上去
- 多项目调度已经"验收通过"，但各仓还没 push、没合

**不该用 end 的情况：** 只想中途存一下（自己 `git commit` 就行）；只要审查（[review](jj-review.md)）；不允许 push 的场合。

收工结束时 Agent 回两行：`合并状态：已合并到：<目标分支>` 或 `合并状态：已回退：<原因>`，以及 `当前分支：<现在所在分支>`。分类表只在合不了 / dry_run 时出现。调度里显示「验收通过」**不等于**已经合进 dev。**end 只做 Git**：不写 ralph `run.json`、不把任务「关死」。归档后再改仍用 [ralph](jj-ralph.md) 同编号 resume。

## 开始前

1. 改完了、验过了——end 不会替你验收
2. 知道要合进哪条分支。不说的话按 `dev` → `develop` → `main` 顺序取第一个存在的
3. 当前所在分支就是这个任务的工作分支——end 在你所在的分支上收工，不会替你切

## 第一次这样用

合入目标默认：有 `dev` 用 `dev`，否则 `develop`，再否则 `main`。git log 里的 `Merge #N into staging`、仓库里同时有 `staging` 分支、构建脚本名带 staging，**都不算**改默认。要合预发必须写 `integration=staging`。任务 / 合并 / 需求说不清就先问，不要臆造、不要挑一边。

**你说：**

```text
$jj-end
```

**Agent 会做：**

1. 先打印一行计划：`工作分支 → 合入分支（来源：你指定 / 文档约定 / 默认规则）`，让你有机会当场拦住
2. `git fetch`，看清当前分支、有没有未提交改动、和远端差多少
3. 只提交 **这个任务的文件**，中文提交信息（`类型(范围): 说明`）；无关的临时文件、本地转储不会被带进去
4. 同步远端工作分支（能快进就快进，否则合并），再推工作分支
5. 切到合入分支，同步到最新，把工作分支合进来，再推
6. 回到工作分支

**你会看到：** 最后一段报告——工作分支 / 合入分支 / 提交 hash 与标题 / 推了哪些分支 / 合并有没有发生。

**怎样算做完：** 工作分支和合入分支都推到了远端。只推了工作分支不算收工。

## 常用说法

```text
$jj-end
收工，合到 dev
$jj-end integration=staging
$jj-end dry_run=true
```

最后一句只打印会做什么（工作分支、合入分支、会不会提交 / 合并 / 推送），不改仓库。

## 做完之后

| 情况 | 会怎样 |
|------|--------|
| 做完实现，Agent 主动说要收工 | 这是设计内的：实现完成且你没禁止推送时，它会先打印一行计划再执行。不想推就明说「先别推」「只提交不推」 |
| 遇到合并冲突 | 先把冲突文件分类打成表。能一句话说清怎么合、不用替产品做决定的，自己合完继续收工；判不了的（同一个开关两边相反、二进制、密钥）**整段中止**、回到工作分支，把表交给你。不会只解一半 |
| 推送失败 | 停在工作分支，把远端的报错给你 |
| 想合进 staging / 预发 | 必须明说 `integration=staging`，或仓库文档写明收工分支是它。git log 里一堆 `Merge into staging`、有个 `staging` 分支、构建脚本名里带 staging——**都不算**约定 |

## 硬规矩

- 不 `force push`、不删分支、不改 git 配置
- 不用 `pull --rebase`（除非你明确要求）
- 不把无关文件、临时脚本、密钥一起提交
- **只许工作分支合进 `dev`**，禁止把 `dev` 合进功能分支
- 冲突默认自己合：两边各自多出来的行为都留下；禁止整文件 `--ours/--theirs`
- 不会只推了工作分支就说"收工成功"
- 合并中止不算成功；不会留下半截合并；不能因为「看起来像逻辑」就整单中止

## 记录在哪

只在 Git 里：提交、分支、远端。end 不写任何任务文件。
