# dispatch — 多个项目一起派

一个需求要改好几个项目时：**先给你看预览 → 你批准 → 派到各项目 → 中断了能接着做**。谁在做、是否批准、做到哪，都记在调度记录里，不靠聊天记忆。dispatch 不负责编写迁移代码（那是 [same](jj-same.md) 的事），也不 push、不合分支（那是 [end](jj-end.md) 的事）。

## 写法

| 工具 | 写法 |
|------|------|
| Codex | `$jj-dispatch …` |
| Claude / Grok / Qoder | `/jj-dispatch …` |

## 适用与边界

**用得当：**

- 一次要改 **好几个** 项目，想统一批准、统一盯进度
- 需要"先看一眼再派"，以及中断后能接着做

**别用在：**

| 你想做的 | 去这里 |
|----------|--------|
| 只改一个仓 | [ralph](jj-ralph.md) |
| 就是要把 A 的能力迁到 B、不需要统一批准 | [same](jj-same.md) |
| 只想提交、合分支 | [end](jj-end.md) |

## 开始前

1. **源仓库已经 commit**——没提交会在派发时被拦住
2. 每个目标仓 **分支对得上这个任务**；拿不准的，Agent 会问，你要能回答
3. **批准得由你本人说**——聊天里随口一句"行"不算正式批准，Agent 会明确问一次

## 第一次这样用

**你说（在任意一个业务仓的对话里，不用先建控制仓）：**

```text
$jj-dispatch 把 README 的装依赖从 npm 改成 pnpm，预览分发到项目A、项目B、项目C
```

**Agent 会做：**

1. **预览（只读）**——给你一张分支表，这一步 **不写任何状态**
2. **等你批准**——你说「批准」「可以派」；`NEEDS_CONFIRM` 的项目会单独让你确认
3. **派发**——把任务绑到真实会话，并在各仓准备 Ralph 任务夹。这一步 **不写迁移代码**；`distribution_prompt` 只是统筹索引，不是派单
4. **交接实施**——下一轮 `$jj-same`：写下本轮要交接的任务、到对应仓库调研，再按任务文档带派单前缀派执行人
5. **盯进度**——中断了再说一句就能接着做；每个项目一段状态（做到哪、证据在哪、下一步）
6. **验收**——某个项目要标"验收通过"，必须同时有：提交、审查结果、真实会话、**证明文件（attestation）**。四样缺一不可，口头说"做完了"不算

**你会看到：** 预览长这样——

```text
## PREVIEW
- delivery / TASK-ID: …
- task_keys（拟派任务）: …
- 分支表：项目 | 打算用的分支 | 当前分支 | 有未提交改动？ | 模式 | 基线动作 | 把握度 | 建议动作
- 需要你：批准任务清单（+ 确认拿不准的分支 / 模式）
```

分支表两列的意思：

| 列 | 含义 |
|----|------|
| 模式（`proposed_mode`） | `S` = 默认，当前分支单会话串行；`W` = 单独隔离工作区 + 命名分支；`P` = 一任务一真实子会话（需你点名，仍用当前分支）。都只是工作方式，不代表更高等级的无人验收 |
| 基线动作（`base_action`） | 分支基线怎么处理：`FF_LOCAL_MASTER`（本地 master 快进）/ `CREATE_FROM_LOCAL_MASTER`（从本地 master 新建）/ `NEEDS_CONFIRM`（要你确认）/ `BLOCKED`（先别派）。新建只从本地 master，不会从远端或 dev 静默新建 |

**怎样算做完：** 每个项目在调度记录里都"验收通过"。注意这 **不等于** 已经 push / 已经合进 dev——那是 [end](jj-end.md) 的事。

## 常用说法

```text
$jj-dispatch 分发当前任务到 项目A和项目D
$jj-dispatch 把 README 装依赖改成 pnpm，预览分发到项目A、项目B、项目C
$jj-dispatch 批准
$jj-dispatch 继续
$jj-dispatch 开始回退 刚才那个 pnpm 的交付
```

## 做完之后

| 你想 | 怎么做 |
|------|--------|
| 推远端 / 合进 dev | 到各项目说 `$jj-end`；调度"验收通过"不会自动 push |
| 某个项目要回退 | 说「回退…」。Agent 先处理调度记录，再探测"推没推、合没合"，**列出选项让你点选**（本地未推常适合 reset，已推已合常适合 revert）；不会自己动 Git，默认不 push |
| 中途改了目标或范围 | 会重新预览、重新要你批准，不会拿旧批准继续派 |

## 记录在哪

统筹层在本机 **`~/.jj-flow`**（可配置）：`DEL-*` 调度记录、回执、证明文件、任务索引。实施层在每个业务仓的 `.workflow/ralph/task-…/`——各仓自己完整的 ralph 任务夹，和当前仓的 ralph 任务同一套合同（Goal / 验收 / Steps）。`delivery` / 任务编号是 Agent 用的，不需要你记。
