# dispatch — 多个项目一起派

**它帮你做什么：** 一个需求要改好几个项目时，在任意一个业务仓的对话里：**先给你看预览 → 你批准 → 派到各项目 → 中断了能接着跑**。谁在做、批没批、做到哪，都记在调度记录里，不靠聊天记忆。

**它不做什么：** 不替你写迁移代码（那是 [same](jj-same.md)）；不 push、不合分支（那是 [end](jj-end.md)）；**Claude 上没有这个入口**（有意为之）。

| 你用的工具 | 怎么喊 |
|------------|--------|
| Codex | `$jj-dispatch …` |
| Grok / Qoder | `/jj-dispatch …` |
| Claude | 没有 |

## 什么时候用

- 一次要改 **好几个** 项目，想统一批准、统一盯进度
- 需要"先看一眼再派"，以及中断后能接着做

**不该用 dispatch 的情况：**

| 你想做的 | 去这里 |
|----------|--------|
| 只改一个仓 | [ralph](jj-ralph.md) |
| 就是要把 A 的能力迁到 B、不需要统一批准 | [same](jj-same.md) |
| 只想提交、合分支 | [end](jj-end.md) |

## 开始前

1. **源仓库已经 commit**——没提交会在派发时被拦住
2. 每个目标仓 **分支对得上这个任务**；拿不准的，Agent 会问，你要能回答
3. **批准得由你本人说**——聊天里随口一句"行"不算正式批准，Agent 会明确问一次

## 第一次这样用

**你说（在任意一个业务仓的对话里，不用先建什么控制仓）：**

```text
$jj-dispatch 把 README 的装依赖从 npm 改成 pnpm，预览分发到项目A、项目B、项目C
```

**Agent 会做：**

1. **预览（只读）**——给你一张表：每个项目 / 打算用的分支 / 现在在哪条分支 / 有没有未提交改动 / 把握度 / 建议动作。这一步 **不写任何状态**
2. **等你批准**——你说「批准」「可以派」；分支或工作区拿不准的项目会单独让你确认
3. **派发**——把任务绑到真实会话上开始做；默认在各项目的功能分支上改，不额外开目录
4. **盯进度**——中断了再说一句就能接着跑；每个项目一段状态（做到哪、证据在哪、下一步）
5. **验收**——某个项目要标"验收通过"，必须同时有：提交、审查结果、真实会话、证明文件。口头说"做完了"不算

**你会看到：**

```text
## 预览
- 任务：…
- 项目分支表：项目 | 打算用的分支 | 当前分支 | 有未提交改动？ | 把握度 | 动作
- 需要你：批准（+ 如有拿不准的项目，确认分支）
```

**怎样算做完：** 每个项目在调度记录里都"验收通过"。注意这 **不等于** 已经 push / 已经合进 dev——那是 [end](jj-end.md) 的事。

## 常用说法

```text
$jj-dispatch 分发当前任务到 项目A和项目D
$jj-dispatch 把 README 装依赖改成 pnpm，预览分发到项目A、项目B、项目C
$jj-dispatch 批准
$jj-dispatch 继续
$jj-dispatch 开始回退 刚才那个 pnpm 的交付
```

## 做完之后

| 你想 | 怎么做 |
|------|--------|
| 推远端 / 合进 dev | 到各项目说 `$jj-end`；调度"验收通过"不会自动 push |
| 某个项目要回退 | 说「回退…」。Agent 先处理调度记录，再探测"推没推、合没合"，**列出选项让你点选**（本地未推常适合 reset，已推已合常适合 revert）；不会自己动 Git，默认不 push |
| 中途改了目标或范围 | 会重新预览、重新要你批准，不会拿旧批准继续派 |

## 进阶

**写整齐一点（可选）**

```text
$jj-dispatch PREVIEW 目标=项目A,项目B,项目C
```

**Grok / Codex 的差别**——Grok 默认 **一个会话串完多个任务**；Codex 可按能力开多个会话。只有主仓有无关脏文件或你明确要隔离时，才会另开独立工作目录（必须挂有名字的分支）。细节见[宿主说明](../concepts-hosts.md)。

## 记录在哪

调度状态默认在你本机 **`~/.jj-flow`**（可配置）。里面的 `delivery` / 任务编号是 Agent 用的，不需要你记。
