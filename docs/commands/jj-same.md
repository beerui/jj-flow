# same — 把能力搬到别的同源仓库

**它帮你做什么：** 项目A 已经做好的能力，按 **项目B / 项目C 自己的写法** 迁过去。迁的是"需求要成立的那几条"，不是整文件复制；每个目标仓单独核对分支、单独验证、单独报结果。

**它不做什么：** 不在当前仓从头做需求（那是 [ralph](jj-ralph.md)）；不做多仓统一批准和派工（那是 [dispatch](jj-dispatch.md)）；不主动 commit / push。

| 你用的工具 | 怎么喊 |
|------------|--------|
| Codex | `$jj-same …` |
| Claude / Grok / Qoder | `/jj-same …` |

## 什么时候用

- 项目A 做完了（通常刚用 ralph 归档），项目B / 项目C 要对齐
- 手上有可当证据的东西：ralph 任务里的交接信息、会话、提交

**不该用 same 的情况：**

| 你想做的 | 去这里 |
|----------|--------|
| 只在当前仓做完一个需求 | [ralph](jj-ralph.md) |
| 好几个仓要统一预览、批准、一起派 | [dispatch](jj-dispatch.md) |
| 只想提交、合分支 | [end](jj-end.md) |

## 开始前

1. **项目A 的改动已经提交**——源仓有未提交改动时，交接信息会标"未就绪"，same 会先让你提交
2. 知道每个目标仓该在哪条分支上改——分支不对 same 会停下来，但你得知道正确答案
3. 在 ralph 归档时如果说过「交接到 项目B 项目C」，交接信息已经准备好了

## 第一次这样用

**你说（在项目A 的对话里，紧接 ralph 做完之后）：**

```text
$jj-same 交接到 项目B 项目C
```

**Agent 会做：**

1. **读交接信息**——从当前 ralph 任务里拿到：改了什么、验收项、哪些不该迁、源提交是哪个。就绪就直接用，不重新分析源仓
2. **确认目标**——你说的「项目B 项目C」对应哪两个仓；说了「三端」但没点名会先问你
3. **逐仓核对分支**——每个目标仓现在在哪条分支、干不干净、是不是这个任务的分支。**不对就停**，让你切好再来；不会"人在哪就改哪"
4. **按目标仓的写法改**——看目标仓已有的结构，用最小改动落地，不硬抄项目A 的文件
5. **验证**——跑相关测试；需要真机 / 真环境验证的会标出来等你确认，不装成已通过

**你会看到：** 每个目标仓一段小结——

```text
## 项目B 小结
- 做法：直接搬 / 适配 / 扩展 / 卡住 / 不适用
- 改动：文件 + 一句话说明
- 验证：跑了什么 / 跳过了什么 / 等你确认什么
- Git：分支 @ 提交；已提交 / 未提交
- 下一步：（可选）
```

**怎样算做完：** 每个目标仓都"改对了、验证过了"。**项目B 成了、项目C 卡住，就只算项目B 完成**，Agent 不会说"全部搞定"。

## 常用说法

**交接（最常见）**

```text
$jj-same 交接到 项目B 项目C
$jj-same 开始交接
```

**只迁一个 / 接着迁下一个**

```text
$jj-same 开始迁移项目D
$jj-same 继续迁项目C
```

**顺手提醒分支**

```text
$jj-same 把阿里云 tracker 迁到项目D，注意别动错分支
```

## 做完之后

| 你想 | 怎么做 |
|------|--------|
| 提交并合分支 | 在每个目标仓说 `$jj-end`——same 不会替你提交 |
| 某个目标卡住了 | 看小结里的"卡住"原因（多半是分支不对或源仓没提交），处理后再说「继续迁项目C」 |
| 项目A 后来又改了 | 提交后再说一次「交接到 项目B」，Agent 会以新的源提交重新对齐 |

## 进阶

### 写整齐一点（可选）

```text
$jj-same
会话=019f…
当前需求=保留密码入口
源=项目A
目标=项目B,项目C
```

日常不需要——same 会自己从 ralph 任务里找交接信息、源提交和目标；只在没有 ralph 任务、要从会话或提交范围里翻证据时才用得上。

### 没有 ralph 任务怎么办

same 会退而从会话记录、提交范围里找证据；都找不到就问你源提交和目标，问清之前不动代码。

### 交接记录里的状态词

维护旧任务时，你可能会看到「准备交接」「更新交接」以及 `parent_snapshot`。它们描述的是交接快照的来源和父版本：

- `REUSE`：现有快照仍新鲜，可以直接复用
- `REFRESH_SOURCES`：先重新读取变化过的源资料
- `REBASELINE`：源基线已经变化，需要重新建立对照
- `BLOCKED`：证据或分支还不够，暂不改目标仓

这些是 Agent 用来判断是否能开始迁移的记录词，日常只要说「开始迁移」或「更新交接」即可。

## 记录在哪

目标仓的 `.workflow/` 下（按类型分目录）。日常看 Agent 的收尾小结就够了。
