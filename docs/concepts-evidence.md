# 什么算「做完了」

## 一句话

**文件和 Git 说了算，聊天不算。**

## 算数 vs 不算数

| 算数 | 不算数 |
|------|--------|
| 任务记录、验收状态 | 聊天里「做完了」 |
| Git 提交 | 会话列表上的状态 |
| 审查结果文件 | 只存在记忆 / 草稿里的内容 |
| 调度里的正式记录 | 模型口头声称「环境 OK」 |
| 运行时沙箱证明（sandbox attestation） | 口头声称「沙箱里验证过」 |

证据不够 → 标记为「还不行 / 卡住」，**不要**当作已通过。

## 三层各管哪些事（知道即可）

1. **本机配置**：项目在哪、调度状态目录在哪  
2. **调度记录**：多个项目哪个项目做了、是否批准
3. **业务仓库**：真正的代码、任务记录、验证说明  

外层与内层可以这样理解：**外层（调度）**决定谁做、是否批准，对应 [dispatch](commands/jj-dispatch.md)；**内层（做事）**是分析 → 改 → 验的循环，对应 [ralph](commands/jj-ralph.md) / [same](commands/jj-same.md)。

调度只存「指向哪里」，不把业务代码正文复制走。
