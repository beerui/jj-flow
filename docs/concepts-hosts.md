# 宿主平台与工作模式（Mode S / W / P）

`jj-flow` 可以在多种主流 AI 编程工具中无缝运行。本页说明不同宿主工具的调用差异，以及在多项目并发协作时的三种工作区拓扑模式（**Mode S、Mode W、Mode P**）。

## 一、支持的宿主工具一览

| 宿主工具 | 对话调用前缀 | 是否支持单仓 `ralph` / 跨仓 `same` | 是否支持多仓调度 `dispatch` | 默认会话习惯 |
| :--- | :--- | :--- | :--- | :--- |
| **Codex** | `$jj-…` | 支持 | 支持 | 支持绑定独立线程或当前会话 |
| **Claude Code** | `/jj-…` | 支持 | 支持 | 默认 **Mode S**（单会话多子代理） |
| **Grok** | `/jj-…` | 支持 | 支持 | 默认 **Mode S**（单会话多子代理，且自动兼容 Claude 资产） |
| **Qoder** | `/jj-…` | 支持 | 支持 | 支持命令补全与多仓调度 |

::: tip Grok 与 Claude Code 资产天然互通
Grok 无需额外配置，即可自动识别并复用 Claude Code 侧安装的技能（`skills/`）、斜杠命令（`commands/`）、命名子代理（`agents/`）以及 `CLAUDE.md` 指令文件。因此这两款工具可以直接共用同一份安装资产。
:::

## 二、三种工作区与会话模式（Mode S / W / P）

当你在 Claude Code 或 Grok 中执行任务（尤其是用 [`$jj-dispatch`](commands/jj-dispatch.md) 同时改多个仓库）时，系统提供三种工作拓扑模式。**日常 95% 的场景默认使用 Mode S 即可：**

| 模式名称 | 简称 | 它是怎么工作的？ | 什么时候用它？ |
| :--- | :--- | :--- | :--- |
| **单会话分支模式（默认）** | **Mode S** | 所有任务都绑定在**当前这一个对话窗口**上，直接在各仓库切好的**功能分支**上修改代码。**不同仓库可以同时派发子代理并行修改**；同一个仓库内部则严格保持串行（一次只有一个写手）。 | **日常默认推荐**。无需手动开多个聊天窗口，也无需创建额外的临时文件夹。 |
| **隔离工作区模式** | **Mode W** | 为任务单独创建一个物理隔离的 **Git worktree 目录**，并检出命名的功能分支（禁止使用游离的 `detached HEAD`）。 | 当前主工作区有正在修改、暂时无法清理的无关脏文件，或者你明确要求“在独立隔离目录里改”时使用。 |
| **独立子会话模式** | **Mode P** | 每个写入任务单独绑定一个 `1:1` 的真实持久子会话（不能用临时 subagent 冒充），代码仍在功能分支上修改。 | 仅当你**显式点名要求**“每个任务单开一个独立子会话”且不需要 worktree 物理隔离时启用。（注：如果既要隔离又要多会话，优先使用 Mode W）。 |

::: info 常见误区澄清：多仓库并行修改不需要开 Mode P
在默认的 **Mode S** 下，只要目标仓库彼此独立（例如同时改 **项目B** 和 **项目C**），主对话本来就可以在同一轮里同时派发两个仓库的实施子代理并行干活，**完全不需要**为此切换到 Mode P。
:::

## 三、「本机半真实试跑」与「真实宿主验收」的区别

在维护 `jj-flow` 自身的自动化测试与自治等级（Autonomy Level）时，我们严格区分两种验证环境（普通用户日常使用无需关心，维护者需遵守此边界）：

| 对比维度 | 本机半真实试跑（`npm run host:trial`） | 真实宿主验收（如 `grok:trial` / 真实会话） |
| :--- | :--- | :--- |
| **运行环境** | 在系统临时目录创建真实 Git 仓库与 worktree 模拟调度流转 | 在真实的 Grok / Codex 宿主会话与真实沙箱中执行 |
| **验证目的** | 快速回归测试控制面状态机、中断恢复（`RECONCILE`）与审查返工闭环 | 证明真实宿主会话绑定与真实运行时沙箱证明（`attestation`）有效 |
| **能否作为上调无人值守等级（A3 / A4）的依据？** | **不能**（属于 `semi-real` 半真实证据） | 必须通过真实宿主试跑验收（Grok 真实试跑已完成 Wave 2 并达到 `A2` 等级；详见 [真实 Host 验收记录](milestones/real-host-acceptance.md)） |

Mode W 与 Mode P 仅代表工作区目录或会话的组织方式，**不能**因为切换了拓扑模式就跳过真实宿主验收或自行上调无人值守等级。
