# 多项目调度 · 一看就懂

**调度是干什么的？**  
一次要改好几个项目时：先出一份名单给你看 → **你点头** → 再按顺序派活 → 进度写在**控制层**，断了也能接着做。

| 叫法 | 是什么 | 默认路径 |
| --- | --- | --- |
| **控制层** | 调度状态目录（谁该做、做到哪、凭证） | **`~/.jj-flow`**（Windows 多为 `%USERPROFILE%\.jj-flow`） |
| 业务仓库 | 真正改代码的项目仓 | 各项目自己的 git 根目录 |

可用 `naming.json` / 环境变量覆盖；用 `jj doctor` 查看当前解析到的 `control_root`。

下面是可点的示意动画（自动播放更轻松）。

## 怎么看

1. 点顶部 **1～9**，或「上一步 / 下一步」
2. 点 **自动播放**，跟着蓝灯走一遍
3. 每一步有一句 **「人话总结」** + 你可以怎么说

图上颜色：

| 颜色 | 意思 |
| --- | --- |
| 蓝（闪） | 这一步正在做 |
| 绿 | 已经做完 |
| 红 | 要返工 |

## 故事线（9 步）

1. 一次改多个项目  
2. 对齐：主仓库是谁、还要哪些  
3. **预览**（只看菜单，不下单）  
4. **你批准**名单  
5. 真派发（先写入控制层再开工）  
6. 先做主仓库  
7. 有凭证再派其它仓库  
8. 返工要开新一轮  
9. 证据齐了才算完成
