# 知识库与记忆热层：经验如何跨任务复用？

在传统的 AI 对话中，一旦关掉当前聊天窗口，你在这一轮辛苦纠正的代码规范、接口约定和踩坑教训就会随之消失。

`jj-flow` 不把易失的聊天记录当作记忆，而是提供了一套**“项目级记忆热层（自动提炼） + 全局跨项目知识库（确认后写入）”**的双层文件机制，让每一次交付沉淀下来的有效经验都能在后续任务中自动复用。

## 一、两层记忆机制一眼对照

| 对比维度 | 项目级记忆热层（Memory Hot Layer） | 跨项目全局知识库（Portfolio Knowledge） |
| :--- | :--- | :--- |
| **存放路径** | `~/.jj-flow/memory/<project_key>.md`（每个项目独立一份） | `~/.jj-flow/knowledge/`（跨项目共享目录与索引） |
| **适用范围** | **当前这一个仓库**的高频踩坑结论、模块潜规则与目录约定 | **同一项目族或多个关联仓库**通用的架构规范、迁移模式与公共约定 |
| **如何产生？** | 当 `ralph` 任务归档时，自动从本任务的 `findings.md` 中提炼“可复用结论”写入待确认列表 | 当你在 [`$jj-init`](commands/jj-init.md) 或 [`$jj-ralph`](commands/jj-ralph.md) 对话中主动说“写入知识库”并**经你确认后**写入 |
| **如何被复用？** | 在该项目开新任务、续接任务或多仓派发时，自动选取最相关的条目（有条数上限，避免撑爆上下文）注入提示词 | 开新 `ralph` 任务时，自动按关键词检索当前项目或同项目族的相关条目并按需挂载 |

## 二、项目级记忆热层（`~/.jj-flow/memory/`）是怎么工作的？

每个业务仓库在本机都有一份轻量的 Markdown 记忆文件 `~/.jj-flow/memory/<project_key>.md`，它的生命周期分为三步：

1. **归档自动提炼（Promote）**：每当你完成一个 `ralph` 任务并归档时，系统会自动扫描该任务的 `findings.md`，将其中具有后续复用价值的规律（如“本仓库弹窗统一使用 `showConfirmDialog` 而非原生 `alert`”）提取为记忆热层中的待确认条目。
2. **确认与置顶（Confirm）**：经你确认的条目（或通过维护命令 `jj ralph knowledge-confirm` 确认）会被标记为“已确认”并优先置顶展示。
3. **定量精准注入（Retrieve）**：下次你在同一个项目开启新任务时，系统会自动注入少量相关性最高的热层条目（已确认条目优先，严格限制注入条数，绝不盲目塞入无关长文）。

## 三、跨项目全局知识库（`~/.jj-flow/knowledge/`）是怎么工作的？

当你有多个同源仓库（例如 **项目A、项目B、项目C** 组成的项目族）时，某些经验是全家族通用的：

* **首次批量建库**：在新仓库或项目族根目录调用 [`$jj-init`](commands/jj-init.md)，Agent 会扫描各仓库已有的 `knowledge-contribution.json`，列出待导入清单，经你批准后统一写入 `~/.jj-flow/knowledge/`。
* **单次任务顺手沉淀**：在一轮 `ralph` 任务归档后，如果你觉得这次总结的规律对其他兄弟仓库也很有用，可以直接在对话里说：
  ```text
  把这个结论写入知识库
  ```
  Agent 会先展示拟写入的标题与内容摘要，**经你确认后**正式写入知识库。

::: tip 核心安全承诺：未经确认，聊天内容绝不自动污染规范库
你在对话中随口讨论的草稿或临时尝试，**绝不会**被静默写进全局知识库或项目地图。一切持久化规范沉淀都经过文件留痕与你的明确确认。
:::
